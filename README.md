# 地图画控制台

这是一个本机地图画工作台：制作投影、管理任务，并让 Minecraft 机器人按指定坐标铺设平滑石和 16 色地毯。桌面端与浏览器共用页面、任务、进度和设置。

本项目基于 [aaeddy/wolfxbot](https://github.com/aaeddy/wolfxbot) 的地图画机器人流程扩展。源码采用 [MIT 许可证](LICENSE)，原作者声明已保留；SlopeCraft/imageCutter 的参考关系和 npm 组件见[来源与第三方说明](THIRD_PARTY_NOTICES.md)。

## 开始前记住

- 打开控制台**不会自动进服或开铺**；只有点任务上的“开始建造”并确认后，机器人才启动。
- 机器人建造的是 `schem/` 中的 `.schem`，不是 `.litematic` 原始投影。
- “任务起点”是投影内部 `(0,0,0)` 对应的世界坐标；第一条平滑石实际从 X+1 开始。“建造传送落点”则是机器人传送后站的位置，不要混填。
- 程序失败后会停止，不会自动反复重连。同一任务再次启动时会读取已有进度并检查未完成区域。
- 进度条用于续建，不保证世界中的每一块都正确；完工后用“检查漏铺”核对。

## 首次安装

下载的源码不含账号设置、投影、任务进度或预编译桌面程序。Windows 用户先安装 [Node.js](https://nodejs.org/en/download)（项目已用 Node.js 22 测试），下载并解压仓库，然后在该文件夹空白处打开 PowerShell：

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd run dashboard
```

首次打开控制台会自动从示例生成本机 `config.js`。浏览器打开 `http://127.0.0.1:32124`，先到“仓库与领地”解锁填写服务器、主机器人、领地、材料桶、食物箱和丢弃点；“建造任务”页再填写建造传送落点。单人模式可以不填第二机器人。缺少必填信息时，点“开始建造”会直接列出缺项，机器人不会登录。`0,64,0` 是示例坐标，请替换为实测位置。

“登录缓存标签”是微软授权资料的标识，可自行取名；“游戏名”是进服后显示的角色名。两者不是同一项，不必填成一样。这两项都可在网页修改；第二机器人只在双人模式用到。更换第二机器人的登录标签后，需要重新授权左账号。

此时还没有你的投影和任务；可以先到“图片制作”生成文件，或在“建造任务”页上传自己的 `.litematic`。添加任务也不会自动开铺。真正点击“开始建造”前，还需核对下方“场地与坐标”说明。

### 可选：使用桌面窗口

桌面窗口是可选功能，需要自行编译。先安装 [.NET 10 SDK](https://learn.microsoft.com/dotnet/core/install/windows) 和 [Microsoft Edge WebView2 Runtime](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)，然后在项目目录执行：

```powershell
dotnet publish '.\桌面控制台\MapArtController.csproj' -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o '.\桌面控制台\publish'
& '.\桌面控制台\publish\地图画控制台.exe'
```

在桌面窗口点“启动网页”即可使用建造任务、图片制作和仓库页面；两端共享同一份数据。桌面程序仍需与 Node.js 项目放在一起，不能单独复制 EXE 到另一台电脑运行。

若出现 `EADDRINUSE`，表示 32124 端口已有网页服务；回到已有窗口，不要重复启动。

## 一张图的使用流程

### 1. 制作或导入文件

已有 `.litematic`：在“建造任务”页拖入投影，或放入 `投影文件/`，再转换成 `schem/` 中的 `.schem`。页面可预览、重转投影，也可将不需要的投影移入系统回收站。修改了投影时建议用新文件名，以免误用旧进度。

只有普通图片：到“图片制作”页上传图片，设置尺寸、比例、缩放质量和颜色模式。先点“先转换预览（不保存）”，满意后再点“生成投影并转换为 schem”。生成 `.litematic`、`.schem` 和材料清单后，还需要自己建任务。原图不会被移动或删除；裁剪只在内存中进行，不会留下大量中间图片。

图片最多分成 64 块，每块按 128×128 像素处理，边缘不足自动补白。颜色模式为 RGB+、Lab94、Lab00、XYZ；Floyd–Steinberg 抖动仿色固定启用。颜色转换算法参考 SlopeCraft，但不保证与其逐像素完全一致；开工前请看预览。图片转换和机器人施工不能同时进行。

### 2. 核对坐标和场地

“仓库与领地”页可编辑服务器、机器人名称、领地名称、材料桶、食物箱和丢弃点。补给食物只能选一种：熟鳕鱼、面包或熟猪排；食物箱需备有选中的食物，机器人会按该选择取用并归还剩余食物。页面平时锁定；场地确实搬迁时，先停止机器人，再解锁、修改并确认保存。保存配置不会移动游戏内的箱子或领地。

回到“建造任务”页核对“建造传送落点”，它必须与机器人执行子领地传送后实际站的位置一致。新建任务时填写 `.schem` 本地 `(0,0,0)` 对应的**投影内部起点** X/Y/Z；它不是第一块平滑石的位置。比如内部起点填 `100,70,200`，第一条平滑石从 `101,70,200` 开始，第一块地毯从 `101,70,201` 开始。下一层若正好叠在上一层上方，通常内部起点 X/Z 不变、Y 加 1。页面建议值只是提示，开工前仍要自己核对。

投影按原始 0° 方向施工，不提供旋转。确认子领地落点安全、材料可取、地图画下方有支撑方块；正常建造不需要梯子。

### 3. 建任务并开铺

选择本次真正要铺的 `.schem`，填写任务名和起点，点击“添加任务”。添加任务本身不会开工。可以先点击任务卡上的“开工前检查”，再选择单人或双人模式，点击该任务的“开始建造”。

- 单人模式：一台机器人铺整张。
- 双人模式：右机器人先铺完整条平滑石，然后两台机器人分别铺左右半张。首次使用前需授权左账号：点击桌面端“授权左机器人”，或运行 `npm.cmd run login-left`。

两台机器人的授权缓存分开保存。如果遇到账号认证报错，可先运行 `npm.cmd run auth-check-right` 或 `npm.cmd run auth-check-left` 核对对应游戏名和凭据；这两个检查只验证账号，不进入游戏服务器，也不会开铺。

运行中可在“运行记录”看日志，必要时点“停止机器人”。不要从两个窗口同时启动不同任务；桌面和浏览器虽然共用数据，但都能发出操作指令。

### 4. 完工后检查

“检查漏铺”会进服逐格读取实际方块，报告缺失、错色和未加载区域，**不会放置或破坏方块**。“上次结果”显示最近一次检查的快照；游戏中手动改过方块后要重新检查。任务卡的进度条不代替复检。

“删除”只移除任务列表记录，不删除 `.litematic`、`.schem` 或 `state/` 续建文件。

## 几个容易混淆的位置

| 名称 | 设置位置 | 用途 |
| --- | --- | --- |
| 任务起点 X/Y/Z | 新建任务 | `.schem` 本地 `(0,0,0)` 在世界里的位置；第一条平滑石在 X+1 |
| 建造传送落点 | 建造任务页 | 确认机器人传送到子领地后站在哪里 |
| 材料领地落点、桶和箱子 | 仓库与领地页 | 确认取料传送和材料寻路 |
| 两个领地名称 | 仓库与领地页 | 组成机器人使用的领地传送指令 |

修改场地设置后，已经运行的机器人不会中途切换到新坐标；请先停止，再启动下一次施工。领地名称和坐标设置不会改变游戏内的领地位置。

## 进度和文件放在哪里

```text
地图画/
├─ 投影文件/          .litematic 投影
├─ schem/              机器人使用的 .schem
├─ state/              任务、续建进度、复检结果
├─ 桌面控制台/          可选桌面端源码，编译后生成 EXE
├─ dashboard.js         网页服务
└─ painting_v2.js       建造引擎
```

同一 `.schem` 内容、同一起点会沿用原进度；投影内容或起点改变会生成新进度。不要为了重启而手动清空 `state/`。想保留旧版本投影时，给新文件换个名称。

程序会逐格确认服务器的放置结果，不靠批量盲放；不要为了追求速度随意缩短延时。机器人会检查血量和饥饿值，按场地设置取料、补给和处理多余背包物品。投影只能包含受支持的 16 色地毯和平滑石；其它方块会使任务停止。

## 出错时怎么处理

- **`Teleport for build/material did not reach`**：传送后的实际位置与保存的落点不一致。核对日志的 `last position` 和游戏内坐标，再改对应落点；程序不会跨领地寻路。
- **`ECONNRESET`、`invalid_player_movement`、被踢**：先检查账号所在位置、网络和服务器状态，不要频繁重开。
- **开箱、吃东西或放置超时**：服务器可能没有及时响应，也可能是目标方块、箱子或站位异常。核对日志最后一个目标和现场后再试，不能仅凭超时判定已经放好。
- **主号明显变卡**：先点“停止机器人”，等服务器恢复流畅再查看日志。
- **任务名称正确但图案不对**：立即停止，核对任务卡选择的 `.schem`，以及日志开头的 `schematic=schem/文件名.schem`。不要等整张铺完才检查。

<details>
<summary>进阶操作：命令行与修复（按需展开）</summary>

日常操作优先用桌面或网页。需要检查程序或在网页不可用时手动处理，可在项目目录执行：

```powershell
npm.cmd run check
npm.cmd run convert -- --input '投影文件\44.litematic' --output 'schem\44.schem'
npm.cmd run inspect
npm.cmd run verify
npm.cmd run repair
```

`check` 是离线代码和沙箱测试，不登录游戏；`inspect` 只读取当前 `config.js` 指向的投影。`verify` 会进服做只读复检；`repair` 会进服按复检结果补缺、实际放方块，并在结束后再检查。命令行模式使用 `config.js` 当前目标，不会自动选中网页当前任务，运行前要核对文件和坐标。

`repair` 的无梯子路线已通过本地沙箱测试，**尚不能保证所有服务器现场都可正常补缺**。首次实际使用请先盯着少量缺口验证，遇到未加载区块、障碍物或放置未确认时停止检查。

桌面端关闭由它启动的网页服务时，若机器人或图片转换还在运行，会先请求安全停止。由其他 PowerShell 窗口启动的网页服务，需要回到那个窗口关闭；桌面端不会强行结束它。
